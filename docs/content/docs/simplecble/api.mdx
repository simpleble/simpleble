## Calling convention

Functions with an `out_error` parameter require the address of an error variable initialized to `NULL`. They release its previous error, then leave it `NULL` on success or fill it on failure. Inspect the error before reusing the variable. A zero, `false`, or `NULL` result alone does not identify failure. Release the final error with `simpleble_error_release(&error)`.

Callback setters without `out_error` require valid handles. Pass `NULL` as the callback to unregister it. Notification subscriptions and advanced Dongl pairing setters are fallible and retain `out_error`.

## Data types and ownership

| Result | Release with |
| --- | --- |
| Allocated identifiers, addresses, read buffers, and local characteristic values | `simpleble_free(pointer)` |
| Error object | `simpleble_error_release(&error)` |
| Backend, adapter, or remote peripheral handle | The matching `simpleble_*_release_handle(handle)` |
| Local peripheral, service, or characteristic handle | The matching `simpleble_local_*_release_handle(handle)` |
| Service snapshot, including its payload, characteristics, and descriptors | `simpleble_service_release(&service)` |
| Manufacturer data snapshot | `simpleble_manufacturer_data_release(&data)` |

Service and manufacturer structs use allocated arrays with lengths/counts. Empty arrays have a zero count and a `NULL` pointer. Their release functions free the contents and zero the caller-owned struct. Release a result before filling the same struct again. Characteristics and descriptors inside a service belong to that service; copying a struct does not duplicate its allocations.

`simpleble_uuid_t` remains a value type containing `char value[37]`: space for a UUID string and its NUL terminator. Remote characteristic capabilities are the five `can_*` boolean fields. Local characteristic capabilities use the `SIMPLEBLE_LOCAL_CHARACTERISTIC_*` bit flags combined with `|`.

Error messages, version strings, native pointers, and callback payloads are borrowed. Scan-found and scan-updated callbacks are the exception for handles: each call transfers an owned peripheral handle that the application must release. Other callback handles refer to the object used for registration.

## Errors [#errors-functions] [toc]

`simpleble_err_t` classifies failures; test the error pointer for success.

| Code | Meaning |
| --- | --- |
| `SIMPLEBLE_ERROR_INVALID_ARGUMENT` | A required argument is NULL or otherwise invalid. |
| `SIMPLEBLE_ERROR_OUT_OF_MEMORY` | Memory allocation failed during an operation. |
| `SIMPLEBLE_ERROR_OBJECT_NOT_INITIALIZED` | A SimpleBLE object has not been initialized. |
| `SIMPLEBLE_ERROR_INVALID_BACKEND_REFERENCE` | An internal object reference cannot be resolved. |
| `SIMPLEBLE_ERROR_PERIPHERAL_NOT_CONNECTED` | A GATT read, write, subscription, or unsubscription requires a connected peripheral. |
| `SIMPLEBLE_ERROR_GATT_SERVICE_NOT_FOUND` | The requested service UUID is absent from the discovered GATT services. |
| `SIMPLEBLE_ERROR_GATT_CHARACTERISTIC_NOT_FOUND` | The requested characteristic UUID is absent from the selected GATT service. |
| `SIMPLEBLE_ERROR_GATT_DESCRIPTOR_NOT_FOUND` | The requested descriptor UUID is absent from the selected GATT characteristic. |
| `SIMPLEBLE_ERROR_OPERATION_NOT_SUPPORTED` | The requested operation is not supported by the adapter or characteristic, or is unavailable in the library implementation. |
| `SIMPLEBLE_ERROR_OPERATION_FAILED` | An operation failed without a more specific exception classification. |
| `SIMPLEBLE_ERROR_WINRT_ACCESS_DENIED` | Retrieving a WinRT asynchronous result raised hresult_access_denied. |
| `SIMPLEBLE_ERROR_WINRT_EXCEPTION` | Retrieving a WinRT asynchronous result raised another hresult_error. |
| `SIMPLEBLE_ERROR_CORE_BLUETOOTH_EXCEPTION` | A CoreBluetoothException containing a diagnostic message. |
| `SIMPLEBLE_ERROR_UNCLASSIFIED_EXCEPTION` | An exception has no dedicated error classification. |
