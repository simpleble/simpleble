<ApiSection title="Local API" id="local-api">

The Local API is how this host advertises and serves GATT. `SimpleBLE::Peripheral` is a remote device; `SimpleBLE::Local::Peripheral` is this host. Create a local peripheral with [`Adapter::create_local_peripheral()`](#simpleble-adapter).

## SimpleBLE::Local::CharacteristicCapability [#simpleble-local-characteristiccapability]

Capabilities are passed to `add_characteristic` as a `std::set`. Each characteristic needs at least one.

| Enumerator | Meaning |
| --- | --- |
| `READ` | Remote centrals can read |
| `WRITE_REQUEST` | Remote centrals can write with a response |
| `WRITE_COMMAND` | Remote centrals can write without a response |
| `NOTIFY` | Remote centrals can subscribe to notifications |
| `INDICATE` | Remote centrals can subscribe to indications |

<ApiSection title="Simulation API" id="simulation-api">

The classes in `SimpleBLE::Simulation` build a simulated BLE environment of adapters and devices. While an [Environment](#simpleble-simulation-environment) is active, the Simulator backend reports its adapters, and the regular [Adapter](#simpleble-adapter) and [Peripheral](#simpleble-peripheral) API scans for, connects to and talks with the simulated devices. Include `<simpleble/Simulation.h>` to use them.

<Callout type="warn" title="Experimental">
The Simulation API is experimental and may change between minor releases. It is available in C++ only for now.
</Callout>

For a walkthrough, see [Build a Simulation](./simulation/build-a-simulation). [Timing and Radio Model](./simulation/timing-and-radio-model) explains how traffic is timed, and [Fidelity and Limits](./simulation/fidelity-and-limits) covers what the simulation does and does not model.

| Enumerator | Meaning |
| --- | --- |

| `WRITE_REQUEST` | The central can write with a response |

| `INDICATE` | The central subscribed to indications |

## SimpleBLE::Simulation::AttStatus [#simpleble-simulation-attstatus]

ATT status returned by a device to a request. The underlying type is `uint8_t`. Application errors (0x80-0x9F) can be returned with a `static_cast`.

| Enumerator | Value |
| --- | --- |
| `SUCCESS` | `0x00` |
| `INVALID_HANDLE` | `0x01` |
| `READ_NOT_PERMITTED` | `0x02` |
| `WRITE_NOT_PERMITTED` | `0x03` |
| `INSUFFICIENT_AUTHORIZATION` | `0x08` |
| `INVALID_ATTRIBUTE_VALUE_LENGTH` | `0x0D` |
| `UNLIKELY_ERROR` | `0x0E` |
| `VALUE_NOT_ALLOWED` | `0x13` |

## SimpleBLE::Simulation::TxStatus [#simpleble-simulation-txstatus]

Result of queueing a notification or indication with `Device::notify()` or `Device::indicate()`.

| Enumerator | Meaning |
| --- | --- |
| `QUEUED` | Queued for the next connection events |
| `BUSY` | TX buffers are full, or an indication awaits confirmation |
| `NOT_SUBSCRIBED` | The central has not subscribed to this characteristic |
| `NOT_CONNECTED` | The connection has closed |
