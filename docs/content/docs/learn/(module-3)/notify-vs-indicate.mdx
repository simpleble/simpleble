A read tells you a value at one moment. To follow a value as it changes, your program subscribes, and the device sends each new value on its own. In this lesson your computer subscribes to notifications from the course peripheral's Counter and prints every value it receives.

## Subscribe instead of reading

Instead of reading a value again and again, a central subscribes to the characteristic, and the peripheral sends each new value as it sets it. The central learns of every change as it happens, without asking.

To subscribe, the central writes the characteristic's Client Characteristic Configuration descriptor, the CCCD, `0x2902`, that you met in [GATT Services and Characteristics](/learn/gatt-services-and-characteristics). The value `0x0001` turns on notifications, `0x0002` turns on indications, and `0x0000` turns both off. SimpleBLE writes the CCCD for you when you call `notify()` or `indicate()`, and clears it when you unsubscribe.

## Notifications and indications

A notification is sent with no reply. The peripheral can send several in one connection event, so notifications suit streams of values, such as sensor readings.

An indication waits for a confirmation. The peripheral sends the next indication only after the central confirms the last one, so only one is on its way at a time. Indications are slower, and each confirmation tells the peripheral that the value arrived. They suit state changes that must not be missed, such as an alarm.

<NotifyIndicateDiagram />

A characteristic's properties say which of the two it supports. In a Bluetooth log, a notification is one packet, and an indication is followed by its confirmation. Open a log in the [Bluetooth HCI Log Viewer](https://simpleble.org/tools/bluetooth-hci-log-viewer) to see both.

## Subscriptions in SimpleBLE

`notify()` subscribes to a characteristic's notifications. From then on, SimpleBLE delivers each value to your callback, or to the flow or stream that the call returns, until you unsubscribe or the connection ends. For a characteristic that indicates, `indicate()` subscribes to its indications and works the same way.

In the C++, C, Python, Java and Delphi programs below, the callback runs on a SimpleBLE thread that also delivers every other event, so those programs can sleep while values arrive. The other languages receive each value on the program's own event loop, task or coroutine, so they wait without blocking it. Either way, keep the code that handles a value short: print or store the value, and return. [Concurrency](/fundamentals/concurrency) explains the rules.

## Subscribe to Counter

Start the course peripheral as in [Connect to a BLE Device](/learn/connect-to-a-ble-device#start-the-course-peripheral). This program finds it and connects, as in the last lessons. It subscribes to Counter's notifications for 5 seconds, prints each value, then unsubscribes and disconnects. In Kotlin Multiplatform and Android, collecting the flow subscribes, and the timeout that ends the collection unsubscribes.

```cpp
#include <algorithm>
#include <chrono>
#include <cstdint>
#include <iostream>
#include <string>
#include <thread>
#include <simpleble/SimpleBLE.h>

const std::string SERVICE = "76a60001-a8e9-4660-bc7b-ed8d93a6849e";
const std::string COUNTER = "76a60003-a8e9-4660-bc7b-ed8d93a6849e";

bool advertises_service(SimpleBLE::Peripheral& device) {
    for (auto& service : device.services()) {
        if (service.uuid() == SERVICE) return true;
    }
    return false;
}

uint32_t to_uint32(const SimpleBLE::ByteArray& bytes) {
    uint32_t value = 0;
    for (size_t i = 0; i < bytes.size() && i < 4; i++) {
        value |= uint32_t(bytes[i]) << (8 * i);
    }
    return value;
}

int main() {
    auto adapter = SimpleBLE::Adapter::get_adapters().at(0);
    adapter.scan_for(5000);

    auto results = adapter.scan_get_results();
    auto found = std::find_if(results.begin(), results.end(), advertises_service);
    if (found == results.end()) {
        std::cout << "Course peripheral not found. Start it and run this program again." << std::endl;
        return 1;
    }
    auto peripheral = *found;

    std::cout << "Connecting to " << peripheral.address() << std::endl;
    peripheral.connect();
    std::cout << "Connected" << std::endl;

    peripheral.notify(SERVICE, COUNTER, [](SimpleBLE::ByteArray value) {
        std::cout << "Notification: " << to_uint32(value) << std::endl;
    });
    std::this_thread::sleep_for(std::chrono::seconds(5));
    peripheral.unsubscribe(SERVICE, COUNTER);

    peripheral.disconnect();
    std::cout << "Disconnected" << std::endl;
    return 0;
}
```

```c
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <simplecble/simplecble.h>

#ifdef _WIN32
#include <windows.h>
#define sleep_seconds(seconds) Sleep((seconds) * 1000)
#else
#include <unistd.h>
#define sleep_seconds(seconds) sleep(seconds)
#endif

static const simpleble_uuid_t SERVICE = {"76a60001-a8e9-4660-bc7b-ed8d93a6849e"};
static const simpleble_uuid_t COUNTER = {"76a60003-a8e9-4660-bc7b-ed8d93a6849e"};

static bool advertises_service(simpleble_peripheral_t device, simpleble_error_t** error) {
    bool found = false;
    simpleble_service_list_t services = NULL;
    size_t count = simpleble_peripheral_services(device, &services, error);
    for (size_t i = 0; i < count && !found && !*error; i++) {
        simpleble_service_t service = {0};
        simpleble_service_list_get(services, i, &service, error);
        found = !*error && strcmp(service.uuid.value, SERVICE.value) == 0;
        simpleble_service_release(&service);
    }
    simpleble_service_list_release(services);
    return found;
}

// Returns an owned handle to the first device that advertises the course service, or NULL.
static simpleble_peripheral_t find_course_peripheral(simpleble_adapter_t adapter, simpleble_error_t** error) {
    simpleble_peripheral_t peripheral = NULL;
    simpleble_peripheral_list_t results = NULL;
    size_t count = 0;
    simpleble_adapter_scan_for(adapter, 5000, error);
    if (!*error) count = simpleble_adapter_scan_get_results(adapter, &results, error);

    for (size_t i = 0; i < count && !peripheral && !*error; i++) {
        simpleble_peripheral_t device = simpleble_peripheral_list_get(results, i, error);
        if (!*error && advertises_service(device, error)) {
            peripheral = device;
        } else {
            simpleble_peripheral_release_handle(device);
        }
    }
    simpleble_peripheral_list_release(results);
    return peripheral;
}

static void on_notification(simpleble_peripheral_t handle, simpleble_uuid_t service, simpleble_uuid_t characteristic,
                            const uint8_t* data, size_t length, void* userdata) {
    (void)handle;
    (void)service;
    (void)characteristic;
    (void)userdata;
    uint32_t value = 0;
    for (size_t i = 0; i < length && i < 4; i++) value |= (uint32_t)data[i] << (8 * i);
    printf("Notification: %lu\n", (unsigned long)value);
}

int main(void) {
    simpleble_error_t* error = NULL;
    simpleble_adapter_list_t adapters = NULL;
    simpleble_adapter_get_adapters(&adapters, &error);
    simpleble_adapter_t adapter = error ? NULL : simpleble_adapter_list_get(adapters, 0, &error);
    simpleble_adapter_list_release(adapters);

    simpleble_peripheral_t peripheral = error ? NULL : find_course_peripheral(adapter, &error);
    if (!error && !peripheral) {
        printf("Course peripheral not found. Start it and run this program again.\n");
        simpleble_adapter_release_handle(adapter);
        return EXIT_FAILURE;
    }

    char* address = error ? NULL : simpleble_peripheral_address(peripheral, &error);
    if (!error) printf("Connecting to %s\n", address);
    simpleble_free(address);

    if (!error) simpleble_peripheral_connect(peripheral, &error);
    if (!error) printf("Connected\n");

    if (!error) simpleble_peripheral_notify(peripheral, SERVICE, COUNTER, on_notification, NULL, &error);
    if (!error) sleep_seconds(5);
    if (!error) simpleble_peripheral_unsubscribe(peripheral, SERVICE, COUNTER, &error);

    if (!error) simpleble_peripheral_disconnect(peripheral, &error);
    if (!error) printf("Disconnected\n");

    int result = error ? EXIT_FAILURE : EXIT_SUCCESS;
    if (error) fprintf(stderr, "%s\n", simpleble_error_message(error));
    simpleble_error_release(&error);
    simpleble_peripheral_release_handle(peripheral);
    simpleble_adapter_release_handle(adapter);
    return result;
}
```

```java
import java.nio.ByteBuffer;
import java.nio.ByteOrder;

import org.simplejavable.Adapter;
import org.simplejavable.BluetoothUUID;
import org.simplejavable.Peripheral;

public class Subscribe {
    static final String SERVICE = "76a60001-a8e9-4660-bc7b-ed8d93a6849e";
    static final String COUNTER = "76a60003-a8e9-4660-bc7b-ed8d93a6849e";

    static boolean advertisesService(Peripheral device) {
        return device.services().stream().anyMatch(service -> service.uuid().equals(SERVICE));
    }

    static long uint32(byte[] value) {
        return Integer.toUnsignedLong(ByteBuffer.wrap(value).order(ByteOrder.LITTLE_ENDIAN).getInt());
    }

    public static void main(String[] args) throws Exception {
        Adapter adapter = Adapter.getAdapters().get(0);
        adapter.scanFor(5000);

        Peripheral peripheral = adapter.scanGetResults().stream()
                .filter(Subscribe::advertisesService)
                .findFirst()
                .orElse(null);
        if (peripheral == null) {
            System.out.println("Course peripheral not found. Start it and run this program again.");
            System.exit(1);
        }

        System.out.println("Connecting to " + peripheral.getAddress());
        peripheral.connect();
        System.out.println("Connected");

        BluetoothUUID service = new BluetoothUUID(SERVICE);
        BluetoothUUID counter = new BluetoothUUID(COUNTER);

        peripheral.notify(service, counter, value -> System.out.println("Notification: " + uint32(value)));
        Thread.sleep(5000);
        peripheral.unsubscribe(service, counter);

        peripheral.disconnect();
        System.out.println("Disconnected");
    }
}
```

```rust
use std::time::Duration;

use futures::StreamExt;
use simplersble::{Adapter, Peripheral, ValueChangedEvent};

const SERVICE: &str = "76a60001-a8e9-4660-bc7b-ed8d93a6849e";
const COUNTER: &str = "76a60003-a8e9-4660-bc7b-ed8d93a6849e";

fn advertises_service(device: &Peripheral) -> bool {
    device.services().unwrap().iter().any(|service| service.uuid() == SERVICE)
}

#[tokio::main]
async fn main() {
    let adapter = Adapter::get_adapters().unwrap().remove(0);
    adapter.scan_for(Duration::from_secs(5)).unwrap();

    let results = adapter.scan_get_results().unwrap();
    let Some(peripheral) = results.into_iter().find(advertises_service) else {
        println!("Course peripheral not found. Start it and run this program again.");
        std::process::exit(1);
    };

    println!("Connecting to {}", peripheral.address().unwrap());
    peripheral.connect().unwrap();
    println!("Connected");

    let service = SERVICE.to_string();
    let counter = COUNTER.to_string();

    // The stream ends when you unsubscribe, which ends the task.
    let mut notifications = peripheral.notify(&service, &counter).unwrap();
    let printer = tokio::spawn(async move {
        while let Some(ValueChangedEvent::ValueUpdated(value)) = notifications.next().await {
            println!("Notification: {}", u32::from_le_bytes(value.try_into().unwrap()));
        }
    });
    tokio::time::sleep(Duration::from_secs(5)).await;
    peripheral.unsubscribe(&service, &counter).unwrap();
    printer.await.unwrap();

    peripheral.disconnect().unwrap();
    println!("Disconnected");
}
```

```kotlin
import kotlin.system.exitProcess
import kotlinx.coroutines.runBlocking
import kotlinx.coroutines.withTimeoutOrNull
import org.simplektble.Adapter
import org.simplektble.BluetoothUUID

    println("Connecting to ${peripheral.address}")
    peripheral.connect()

        peripheral.notify(SERVICE, COUNTER).collect { value ->

        }
    }
```

## What you should see

About five notifications, with numbers that count up:

```
Connecting to 7C:2E:0D:A4:58:13
Connected
Notification: 17
Notification: 18
Notification: 19
Notification: 20
Notification: 21
Disconnected
```

The course peripheral sets Counter once a second, so the 5-second subscription receives about five values. The first number depends on how long the course peripheral has been running.

With nRF Connect's GATT server, a value arrives each time you change Counter in the app. Enter its value as four bytes, such as `05 00 00 00`, which the program prints as 5.

## Exercise

Print the time since subscribing next to each value, in milliseconds. Note the time just before `notify()`, and print the difference with each value, the way [BLE Advertising Interval and Discovery Time](/learn/advertising-interval-and-discovery) measured discovery time. Values arrive about 1000 ms apart, because the course peripheral sets Counter once a second.

If the peripheral sent 100 values a second, notifications would keep up, while indications would be limited to one per round trip to the central and back.

## Troubleshooting

- **The program prints `Course peripheral not found`.** Start the course peripheral as in [Connect to a BLE Device](/learn/connect-to-a-ble-device#start-the-course-peripheral). It advertises for 10 minutes and then stops, so start it again if it has been running longer.
- **No values arrive.** The course peripheral stops after 10 minutes, so start it again and run the program. With nRF Connect, a value arrives only when Counter's value changes, so change it in the app while the program waits.
- **Subscribing fails with an error.** The characteristic doesn't support notifications. The program in [GATT Services and Characteristics](/learn/gatt-services-and-characteristics) prints each characteristic's properties, and Counter needs notify. With nRF Connect, enable notify when you create Counter.
