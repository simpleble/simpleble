Every advertisement your adapter receives comes with a signal strength reading, the RSSI. It is the easiest way to tell whether a device is close, moving away or coming back.

## What RSSI measures

RSSI, the received signal strength indicator, is the power of a packet as your adapter received it, in dBm. It is a negative number, and the closer to zero, the stronger the signal. Typical readings run from about -30 dBm with the device touching the computer to about -100 dBm at the edge of range.

The scale is logarithmic. Every 3 dB is half or double the power, and in open space, doubling the distance lowers the RSSI by about 6 dB. That is why RSSI changes fast near the computer and slowly far from it.

## Why readings jump

<RssiTraceDiagram />

Two readings a second apart can differ by 10 dB with nothing moving. The signal reaches your adapter along several paths at once, bouncing off walls, furniture and people, and the copies add up or cancel out. Each advertisement is also sent on three channels at different frequencies, and each frequency fades differently. A hand around a phone or a body between the devices takes off several dB more.

So treat a single reading as noise and an average as the signal. Average the last few readings, and compare the average with a threshold rather than reacting to every value.

## RSSI and distance

Distance estimates need the transmit power. A device that advertises its TX power lets you compute the path loss, the TX power minus the RSSI, and beacons advertise their expected RSSI at one meter for the same purpose. You can see the TX Power Level field in any advertisement with the [BLE Advertisement Decoder](https://simpleble.org/tools/ble-advertisement-decoder).

Even then, the result is a rough range, not a measurement. RSSI answers "near, far or in between" and "getting closer or moving away" well. It does not tell a meter from two meters.

## Watch the signal live

Set `TARGET` to the name of a device you can carry, such as your phone advertising from nRF Connect for Mobile. The program follows that device for fifteen seconds and prints a bar for each reading: the longer the bar, the stronger the signal.

```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <simpleble/SimpleBLE.h>

const std::string TARGET = "My Phone";

int main() {
    auto adapter = SimpleBLE::Adapter::get_adapters().at(0);

    auto report = [](SimpleBLE::Peripheral device) {

        int rssi = device.rssi();

}
```

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <simplecble/simplecble.h>

static const char* TARGET = "My Phone";

static void report(simpleble_adapter_t adapter, simpleble_peripheral_t device, void* userdata) {
    simpleble_error_t* error = NULL;
    char* identifier = simpleble_peripheral_identifier(device, &error);
    if (!error && strcmp(identifier, TARGET) == 0) {
        int rssi = simpleble_peripheral_rssi(device, &error);
        printf("%d dBm ", rssi);
        for (int i = 0; i < rssi + 100; i++) putchar('#');
        putchar('\n');
    }
    simpleble_free(identifier);
    simpleble_error_release(&error);
    simpleble_peripheral_release_handle(device);
}

int main(void) {
    simpleble_error_t* error = NULL;
    simpleble_adapter_list_t adapters = NULL;
    simpleble_adapter_get_adapters(&adapters, &error);
    simpleble_adapter_t adapter = error ? NULL : simpleble_adapter_list_get(adapters, 0, &error);
    simpleble_adapter_list_release(adapters);

    if (!error) {
        simpleble_adapter_set_callback_on_scan_found(adapter, report, NULL);
        simpleble_adapter_set_callback_on_scan_updated(adapter, report, NULL);
        simpleble_adapter_scan_for(adapter, 15000, &error);
    }

    int result = error ? EXIT_FAILURE : EXIT_SUCCESS;
    if (error) fprintf(stderr, "%s\n", simpleble_error_message(error));
    simpleble_error_release(&error);
    simpleble_adapter_release_handle(adapter);
    return result;
}
```

```java
import org.simplejavable.Adapter;
import org.simplejavable.Peripheral;

public class SignalStrength {
    static final String TARGET = "My Phone";

    static void report(Peripheral device) {
        if (!device.getIdentifier().equals(TARGET)) return;
        int rssi = device.getRssi();
        System.out.println(rssi + " dBm " + "#".repeat(Math.max(0, rssi + 100)));
    }

    public static void main(String[] args) throws Exception {
        Adapter adapter = Adapter.getAdapters().get(0);

        adapter.setEventListener(new Adapter.EventListener() {
            @Override
            public void onScanFound(Peripheral device) {
                report(device);
            }

            @Override
            public void onScanUpdated(Peripheral device) {
                report(device);
            }
        });

        adapter.scanFor(15000);
    }
}
```

```rust
use std::time::Duration;

use futures::StreamExt;
use simplersble::{Adapter, Peripheral, ScanEvent};

const TARGET: &str = "My Phone";

fn report(device: &Peripheral) {
    if device.identifier().unwrap() != TARGET {
        return;
    }
    let rssi = device.rssi().unwrap();
    println!("{} dBm {}", rssi, "#".repeat((rssi + 100).max(0) as usize));
}

#[tokio::main]
async fn main() {
    let adapter = Adapter::get_adapters().unwrap().remove(0);

    let mut events = adapter.on_scan_event();
    tokio::spawn(async move {
        while let Some(event) = events.next().await {
            match event {
                ScanEvent::Found(device) | ScanEvent::Updated(device) => report(&device),
                _ => {}
            }
        }
    });

    adapter.scan_for(Duration::from_secs(15)).unwrap();
}
```

```pascal
var
  Bars: Integer;
begin
  if Device.Identifier <> Target then

  Bars := Device.Rssi + 100;

  Adapter.OnScanUpdated := Printer.Report;
```

## Troubleshooting

- **Nothing is printed.** `TARGET` must match the advertised name exactly, including capitals and spaces. Run the program from [Scan for BLE devices](/learn/scan-for-ble-devices) and copy the name from its output.
- **Readings stop after a few seconds.** The device stopped advertising. Keep the nRF Connect advertiser running and the phone's screen on.
- **The RSSI jumps 10 dB with nothing moving.** That is normal for single readings. Average them, as in the exercise.
- **The signal is weaker than expected at close range.** A hand, a case or your body between the devices absorbs 2.4 GHz signals. Hold the phone by its edges, in clear view of the computer.
