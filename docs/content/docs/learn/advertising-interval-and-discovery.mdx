A device doesn't appear the moment your program starts a scan. It appears when one of its advertisements reaches your adapter while the adapter is listening. How long that takes depends on how often the device advertises and how often your computer listens, and it changes from one scan to the next.

## Advertising events and scan windows

A peripheral advertises in advertising events. In each event, it sends its advertisement once on each of the three advertising channels, 37, 38 and 39. Events repeat at the advertising interval, from 20 ms to 10.24 s, and the peripheral adds a random delay of 0 to 10 ms to each one so that two devices with the same interval don't keep colliding. [BLE Advertising](/fundamentals/advertising) covers the channels and the packets.

A scanner listens in turns too. Once every scan interval, it listens on one advertising channel for the length of the scan window, and it uses another channel for the next window. The scan window divided by the scan interval is the duty cycle, the share of time the scanner listens. A window as long as the interval means the scanner listens all the time.

<DiscoveryTimingDiagram />

A device is discovered when one of its advertisements arrives inside a scan window, on the channel that window listens to.

## What decides discovery time

- **The advertising interval.** A device that advertises every 100 ms gives the scanner ten chances a second. One that advertises every second gives it one.
- **The scan duty cycle.** The more of the time the scanner listens, the sooner one of those chances lands in a window.
- **Alignment.** Where the first advertising event falls against the scan windows is luck. The same device can be found on its first advertisement in one scan and on a later one in the next.

Your program doesn't set the scan interval and window: the operating system chooses them when your program starts a scan. The time your program measures also includes the time the operating system takes to start scanning and to deliver the report.

The [BLE Discovery Latency Calculator](https://simpleble.org/tools/ble-discovery-latency-calculator) takes an advertising interval, a scan interval and a scan window, and shows how long discovery takes in typical and slow cases.

## Advertising interval and battery life

Every advertising event costs energy, so a battery-powered device can't advertise fast all the time. Halving the interval roughly doubles the energy the device spends advertising. The usual pattern is to advertise fast while a user is waiting for the device, such as right after it powers on or after a button press, and slowly the rest of the time.

## Measure discovery time

```cpp
#include <atomic>
#include <chrono>
#include <iostream>
#include <string>
#include <thread>
#include <simpleble/SimpleBLE.h>

const std::string SERVICE = "76a60001-a8e9-4660-bc7b-ed8d93a6849e";

int main() {
    std::atomic<bool> found{false};
    auto adapter = SimpleBLE::Adapter::get_adapters().at(0);

    auto check = [&found](SimpleBLE::Peripheral device) {
        for (auto& service : device.services()) {
            if (service.uuid() == SERVICE) {
                found = true;
            }
        }
    };
    adapter.set_callback_on_scan_found(check);
    adapter.set_callback_on_scan_updated(check);

    long long total = 0;
    int count = 0;
    for (int trial = 1; trial <= 5; trial++) {
        found = false;
        auto start = std::chrono::steady_clock::now();
        adapter.scan_start();
        while (!found && std::chrono::steady_clock::now() - start < std::chrono::seconds(10)) {
            std::this_thread::sleep_for(std::chrono::milliseconds(10));
        }
        auto elapsed = std::chrono::duration_cast<std::chrono::milliseconds>(std::chrono::steady_clock::now() - start);
        adapter.scan_stop();

        if (found) {
            std::cout << "Trial " << trial << ": found after " << elapsed.count() << " ms" << std::endl;
            total += elapsed.count();
            count++;
        } else {
            std::cout << "Trial " << trial << ": not found in 10 s" << std::endl;
        }
    }
    if (count > 0) {
        std::cout << "Average: " << total / count << " ms" << std::endl;
    }
    return 0;
}
```

```c
#ifdef _WIN32
#include <windows.h>
#else
#define _POSIX_C_SOURCE 200809L
#include <time.h>
#endif
#include <stdbool.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <simplecble/simplecble.h>

static const char* SERVICE = "76a60001-a8e9-4660-bc7b-ed8d93a6849e";
static volatile bool found = false;

static long long now_ms(void) {
#ifdef _WIN32
    return (long long)GetTickCount64();
#else
    struct timespec now;
    clock_gettime(CLOCK_MONOTONIC, &now);
    return (long long)now.tv_sec * 1000 + now.tv_nsec / 1000000;
#endif
}

static void sleep_ms(long ms) {
#ifdef _WIN32
    Sleep((DWORD)ms);
#else
    struct timespec duration = {ms / 1000, (ms % 1000) * 1000000};
    nanosleep(&duration, NULL);
#endif
}

static void check(simpleble_adapter_t adapter, simpleble_peripheral_t device, void* userdata) {
    (void)adapter;
    (void)userdata;
    simpleble_error_t* error = NULL;
    simpleble_service_list_t services = NULL;
    size_t count = simpleble_peripheral_services(device, &services, &error);
    for (size_t i = 0; i < count && !error; i++) {
        simpleble_service_t service = {0};
        simpleble_service_list_get(services, i, &service, &error);
        if (error) break;
        if (strcmp(service.uuid.value, SERVICE) == 0) found = true;
        simpleble_service_release(&service);
    }
    simpleble_service_list_release(services);
    simpleble_error_release(&error);
    simpleble_peripheral_release_handle(device);
}

int main(void) {
    simpleble_error_t* error = NULL;
    simpleble_adapter_list_t adapters = NULL;
    simpleble_adapter_get_adapters(&adapters, &error);
    simpleble_adapter_t adapter = error ? NULL : simpleble_adapter_list_get(adapters, 0, &error);
    simpleble_adapter_list_release(adapters);

    if (!error) {
        simpleble_adapter_set_callback_on_scan_found(adapter, check, NULL);
        simpleble_adapter_set_callback_on_scan_updated(adapter, check, NULL);
    }

    long long total = 0;
    int count = 0;
    for (int trial = 1; trial <= 5 && !error; trial++) {
        found = false;
        long long start = now_ms();
        simpleble_adapter_scan_start(adapter, &error);
        while (!error && !found && now_ms() - start < 10000) sleep_ms(10);
        long long elapsed = now_ms() - start;
        if (!error) simpleble_adapter_scan_stop(adapter, &error);
        if (error) break;

        if (found) {
            printf("Trial %d: found after %lld ms\n", trial, elapsed);
            total += elapsed;
            count++;
        } else {
            printf("Trial %d: not found in 10 s\n", trial);
        }
    }
    if (!error && count > 0) printf("Average: %lld ms\n", total / count);

    int result = error ? EXIT_FAILURE : EXIT_SUCCESS;
    if (error) fprintf(stderr, "%s\n", simpleble_error_message(error));
    simpleble_error_release(&error);
    simpleble_adapter_release_handle(adapter);
    return result;
}
```

```rust
use std::sync::atomic::{AtomicBool, Ordering};
use std::sync::Arc;
use std::time::{Duration, Instant};

use futures::StreamExt;
use simplersble::{Adapter, Peripheral, ScanEvent};

const SERVICE: &str = "76a60001-a8e9-4660-bc7b-ed8d93a6849e";

fn advertises_service(device: &Peripheral) -> bool {
    device.services().unwrap().iter().any(|service| service.uuid() == SERVICE)
}

#[tokio::main]
async fn main() {
    let adapter = Adapter::get_adapters().unwrap().remove(0);

    let found = Arc::new(AtomicBool::new(false));
    let flag = found.clone();
    let mut events = adapter.on_scan_event();
    tokio::spawn(async move {
        while let Some(event) = events.next().await {
            match event {
                ScanEvent::Found(device) | ScanEvent::Updated(device) => {
                    if advertises_service(&device) {
                        flag.store(true, Ordering::SeqCst);
                    }
                }
                _ => {}
            }
        }
    });

    let mut times = Vec::new();
    for trial in 1..=5 {
        found.store(false, Ordering::SeqCst);
        let start = Instant::now();
        adapter.scan_start().unwrap();
        while !found.load(Ordering::SeqCst) && start.elapsed() < Duration::from_secs(10) {
            tokio::time::sleep(Duration::from_millis(10)).await;
        }
        let elapsed = start.elapsed().as_millis();
        adapter.scan_stop().unwrap();

        if found.load(Ordering::SeqCst) {
            println!("Trial {}: found after {} ms", trial, elapsed);
            times.push(elapsed);
        } else {
            println!("Trial {}: not found in 10 s", trial);
        }
    }
    if !times.is_empty() {
        println!("Average: {} ms", times.iter().sum::<u128>() / times.len() as u128);
    }
}
```

## What you should see

One line for each trial, then the average of the trials that found the device:

```
Trial 1: found after 1294 ms
Trial 2: found after 376 ms
Trial 3: found after 2838 ms
Trial 4: found after 175 ms
Trial 5: found after 1180 ms
Average: 1173 ms
```

The device and the distance stay the same, yet every trial takes a different time. Each scan starts at a different point in the device's advertising schedule: in some trials an advertisement lands in the first scan window, and in others the scanner waits for a later one. The first trial can be the slowest, because it also includes the time the operating system takes to start the scanner.

Your numbers depend on the target's advertising interval and on the scan timing your operating system chooses. The course peripheral leaves its advertising interval to the operating system, which often advertises about once a second, so trials range from a few hundred milliseconds to several seconds.

## Troubleshooting

- **Every trial says not found.** The target isn't advertising the course service, or it is out of range. The course peripheral stops advertising after 10 minutes, so start it again. In nRF Connect, check that the advertiser is on and that its advertising data lists `76a60001-a8e9-4660-bc7b-ed8d93a6849e`.
- **The first trial is much slower than the rest.** The first scan also starts the scanner in the operating system. Leave the first trial out of the average, or run more trials.
- **The times spread from tens to hundreds of milliseconds.** That spread is the alignment this lesson is about. Compare averages over several runs rather than single trials.
- **Android finds nothing when you run the program again right away.** Android allows an app five scan starts in 30 seconds, and each trial starts a scan. Wait 30 seconds before you run the program again.
