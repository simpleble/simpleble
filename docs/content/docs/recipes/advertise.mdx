Advertising is how this host is found. A local peripheral serves GATT, sends advertisements, and waits for a central to connect.

`SimpleBLE::Peripheral` is a remote device. `SimpleBLE::Local::Peripheral` is this host. Create the local peripheral from an `Adapter`, the same object used to scan.

<Callout type="info" title="Available on all supported platforms">
SimpleBLE can host a local peripheral on every supported platform, and every language binding exposes the same flow. Native Android applications must provide their application context with `SimpleBLE::Advanced::Android::set_context()` before creating the local peripheral. SimpleDroidBLE does this for you when you pass a `Context`, and SimpleKtBLE and SimpleFltBLE do it for you without one.
</Callout>

## Flow

1. Get an adapter.
2. Create a local peripheral.
3. Select the advertised service UUIDs, if needed.
4. Add services and characteristics.
5. Register client or write callbacks if you need them.
6. Call `start()`, keep the process alive, then `stop()`.

use futures::stream::StreamExt;
use simplersble::{Adapter, CharacteristicCapability, ClientEvent, LocalCharacteristicEvent};

let adapter = Adapter::get_adapters().unwrap().remove(0);
let peripheral = adapter.create_local_peripheral().unwrap();

peripheral.add_advertised_service("12345678-1234-5678-1234-56789abcdef0").unwrap();

let service = peripheral.add_service("12345678-1234-5678-1234-56789abcdef0").unwrap();
let characteristic = service
    .add_characteristic(
        "12345678-1234-5678-1234-56789abcdef1",
        &[
            CharacteristicCapability::Read,
            CharacteristicCapability::WriteRequest,
            CharacteristicCapability::Notify,
        ],
    )
    .unwrap();
characteristic.set_value(b"ready").unwrap();

let mut characteristic_events = characteristic.on_event();
let echo = characteristic.clone();
tokio::spawn(async move {
    while let Some(event) = characteristic_events.next().await {
        if let LocalCharacteristicEvent::Written(value) = event {
            // Echo the written value to subscribed clients.
            echo.set_value(&value).unwrap();
        }
    }
});

let mut client_events = peripheral.on_client_event();
tokio::spawn(async move {
    while let Some(event) = client_events.next().await {
        if let ClientEvent::Connected(address) = event {
            println!("Client connected: {}", address);
        }
    }
});

peripheral.start().unwrap();

Configure services, characteristics, and advertising before `start()`. While started, update data with `set_value()` rather than rebuilding the GATT table. `set_value()` also publishes the latest value to subscribed clients when the characteristic has `NOTIFY` or `INDICATE` capability.

SimpleBLE permits the same adapter to scan while the local peripheral is started when the platform Bluetooth stack and controller support concurrent scanning and advertising. On Linux, BlueZ and the controller must support both operations at the same time.

## Advertise a beacon

A beacon is a non-connectable local peripheral without services. Manufacturer data carries its payload, such as an iBeacon frame or a format of your own.

<Tabs items={["C++", "Python", "Java", "Rust", "Node.js", "React Native", "Kotlin Multiplatform", "Swift", "Dart", "Delphi", "Android"]}>
<Tab value="C++">

```cpp
auto peripheral = adapter.create_local_peripheral();

// iBeacon: 0x02 0x15, a 16-byte UUID, major, minor, and the measured power at 1 m.
SimpleBLE::ByteArray ibeacon = {0x02, 0x15,
                                0xe2, 0xc5, 0x6d, 0xb5, 0xdf, 0xfb, 0x48, 0xd2,
                                0xb0, 0x60, 0xd0, 0xf5, 0xa7, 0x10, 0x96, 0xe0,
                                0x00, 0x01,  // Major
                                0x00, 0x02,  // Minor
                                0xc5};       // Measured power (-59 dBm)
peripheral.set_advertised_manufacturer_data(0x004c, ibeacon);
peripheral.set_connectable(false);
peripheral.start();
```

Setting data for the same company identifier again replaces it. To change the payload while advertising, call `stop()`, set the data, then `start()` again.

Beacons work on Linux, Windows, and Android. macOS and iOS can't advertise manufacturer data. Windows advertises manufacturer data only from a non-connectable peripheral without services.

## Hosting from C

SimpleCBLE provides the same local-hosting flow through owned local peripheral, service, and characteristic handles. See the [C hosting example](../simplecble/tutorial#local-peripheral-hosting) for creation, start/stop, and cleanup.

## Practical notes

- Keep the process alive after `start()`. Advertising stops when the object is destroyed or `stop()` is called.
- Each characteristic needs at least one capability. In C++, pass them as a `std::set` (an initializer list is enough).
- On Linux, BlueZ must be running and the process must have D-Bus access, as with scanning.
- On macOS, CoreBluetooth reports client connection and disconnection callbacks when the client first subscribes and finally unsubscribes.
- On Windows, the adapter and driver must support the peripheral role. Applications distributed as AppX/MSIX packages should declare `<DeviceCapability Name="bluetooth" />` in `Package.appxmanifest`; ordinary unpackaged executables do not need this manifest declaration. Windows controls the advertised Bluetooth name.
- On Android, request `BLUETOOTH_ADVERTISE` and `BLUETOOTH_CONNECT` at runtime before `start()`.
- On Android, SimpleBLE includes the adapter's system Bluetooth name. Android's public advertising API cannot set an arbitrary per-advertisement name.
- Linux, macOS, and iOS callers that need a platform-specific advertised name can use `set_advertisement_local_name()` from the corresponding `SimpleBLE::Advanced` platform namespace, or its binding equivalent, before `start()`.

For the full C++ walkthrough, see [Advertise, Serve, Publish](../simpleble/peripheral/advertise-serve-publish). For scanning from the other side of the link, see [Scan](./scan).
